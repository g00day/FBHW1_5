## Результат второй контрольной работы: Интернет-магазин рыболовных снастей с системой аутентификации и RBAC

Итогом второй контрольной работы стало полноценное веб-приложение с системой регистрации и входа, ролевой моделью доступа, возможностью управления товарами в зависимости от прав пользователя и административной панелью для управления пользователями.

### 🔐 Аутентификация и авторизация

- **Хеширование паролей bcrypt**  
В серверной части приложения для хранения паролей используется библиотека bcrypt. Пароль пользователя перед сохранением в "базу данных" (in-memory хранилище) хешируется с использованием "соли" (salt), что исключает возможность восстановления исходного пароля при утечке данных. Количество раундов хеширования настроено на оптимальное значение 10.

- **JWT токены (access + refresh)**  
После успешной аутентификации сервер генерирует пару токенов: access-токен со сроком жизни 15 минут и refresh-токен со сроком жизни 7 дней. Access-токен используется для доступа к защищенным ресурсам, refresh-токен — для получения новой пары токенов по истечении access-токена. Refresh-токены хранятся на сервере в Set-коллекции с возможностью инвалидации.

- **Middleware защита маршрутов**  
Созданы два middleware: `authMiddleware` для проверки наличия и валидности access-токена в заголовке Authorization, и `roleMiddleware` для проверки наличия у пользователя необходимой роли. Маршруты защищены с помощью комбинации этих middleware.

### 👥 Ролевая модель доступа (RBAC)

- **Роль "Пользователь"**  
Аутентифицированный пользователь с базовыми правами: просмотр списка товаров, просмотр детальной информации о товаре, получение информации о своем профиле.

- **Роль "Продавец"**  
Расширенные права на управление товарами: создание новых товаров, редактирование существующих товаров. Не имеет доступа к управлению пользователями.

- **Роль "Администратор"**  
Полный доступ ко всем ресурсам приложения: все права продавца + управление пользователями (просмотр списка, просмотр детальной информации, редактирование данных, блокировка учетных записей). Также имеет право на удаление товаров.

- **Роль "Гость"**  
Неаутентифицированный пользователь. Имеет доступ только к маршрутам регистрации, входа и обновления токенов.

### 🛠 Используемые технологии

- **Express.js**  
Backend-фреймворк для создания RESTful API. Реализована маршрутизация запросов, middleware для обработки CORS и JSON, обработка ошибок. Сервер запускается на порту 3000.

- **jsonwebtoken**  
Библиотека для создания и верификации JWT-токенов. Используется для генерации access- и refresh-токенов с разными секретами и временем жизни.

- **React.js + Vite**  
Frontend-библиотека для создания пользовательского интерфейса. Реализованы компоненты для аутентификации, управления товарами и управления пользователями. Vite используется как сборщик и инструмент для быстрой разработки.

- **Axios + Interceptors**  
HTTP-клиент для выполнения запросов к API. Настроены перехватчики запросов для автоматической подстановки access-токена в заголовок Authorization, а также перехватчики ответов для автоматического обновления токенов при получении ошибки 401.

- **Swagger UI**  
Создана спецификация OpenAPI с подробным описанием всех эндпоинтов, схем данных, кодов ответов. Документация доступна по адресу `http://localhost:3000/api-docs` и позволяет тестировать API через удобный веб-интерфейс.

### 🗂 Структура хранения данных

- **In-memory хранилище**  
Для демонстрационных целей данные хранятся в массивах в памяти сервера: `users` для пользователей, `products` для товаров, `refreshTokens` (Set) для валидных refresh-токенов. При перезапуске сервера данные сбрасываются.

- **Сущность "Пользователь"**  
Поля: `id` (nanoid), `email`, `first_name`, `last_name`, `hashedPassword`, `role` ('user' | 'seller' | 'admin'), `isBlocked` (boolean).

- **Сущность "Товар"**  
Поля: `id` (автоинкремент), `title`, `category`, `description`, `price`.

### 🌐 API маршруты

| Категория | Метод | Эндпоинт | Доступ | Описание |
|-----------|-------|----------|--------|----------|
| Auth | POST | `/api/auth/register` | Гость | Регистрация |
| Auth | POST | `/api/auth/login` | Гость | Вход |
| Auth | POST | `/api/auth/refresh` | Гость | Обновление токенов |
| Auth | GET | `/api/auth/me` | Пользователь+ | Профиль |
| Users | GET | `/api/users` | Админ | Список пользователей |
| Users | GET | `/api/users/:id` | Админ | Пользователь по ID |
| Users | PUT | `/api/users/:id` | Админ | Обновление пользователя |
| Users | DELETE | `/api/users/:id` | Админ | Блокировка пользователя |
| Products | GET | `/api/products` | Пользователь+ | Список товаров |
| Products | GET | `/api/products/:id` | Пользователь+ | Товар по ID |
| Products | POST | `/api/products` | Продавец+ | Создание товара |
| Products | PUT | `/api/products/:id` | Продавец+ | Обновление товара |
| Products | DELETE | `/api/products/:id` | Админ | Удаление товара |

### 🧪 Тестирование через Postman

В процессе разработки использовался HTTP-клиент Postman для тестирования всех эндпоинтов API. Проверялись следующие сценарии:

- Регистрация нового пользователя с валидными и невалидными данными
- Вход в систему с получением пары токенов
- Доступ к защищенным маршрутам с корректным и некорректным access-токеном
- Обновление токенов по refresh-токену
- Проверка ролевых ограничений (доступ продавца к созданию товаров, доступ администратора к управлению пользователями)
- Полный CRUD цикл для товаров и пользователей

### 📚 Документация API

Swagger UI предоставляет интерактивную документацию со следующими возможностями:

- Просмотр всех доступных эндпоинтов с grouping по тегам (Auth, Users, Products)
- Детальное описание каждого маршрута: параметры пути, query-параметры, тело запроса, возможные коды ответов
- Примеры запросов и ответов для каждого эндпоинта
- Возможность выполнять тестовые запросы прямо из браузера

Документация доступна после запуска сервера по адресу: `http://localhost:3000/api-docs`

### 🔄 Frontend-приложение

- **Страница входа**  
Форма с полями email и password. После успешной аутентификации токены сохраняются в localStorage, пользователь перенаправляется на главную страницу.

- **Страница регистрации**  
Форма с полями email, first_name, last_name, password. После успешной регистрации пользователь перенаправляется на страницу входа.

- **Управление товарами**  
Просмотр списка товаров в виде карточек. Для продавцов и администраторов доступны кнопки создания нового товара и редактирования существующих. Только администратор может удалять товары.

- **Управление пользователями (админ-панель)**  
Администратору доступен список всех зарегистрированных пользователей с возможностью просмотра детальной информации, редактирования данных (имя, фамилия, роль) и блокировки учетных записей.

- **Автоматическое обновление токенов**  
Настроен axios interceptor, который перехватывает ответы с кодом 401 и автоматически отправляет запрос на обновление токенов, после чего повторяет исходный запрос с новым access-токеном.
